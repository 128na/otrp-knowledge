# スケジュール・発車・積載

> この内容は、OTRP の PR とリリースノートの記述から拾ったものです（2026-11-14 時点）。ゲームの動作やソースコードでは確かめていません。仕様は [OTRP wiki](https://github.com/teamhimeh/simutrans/wiki/OTRP-Home) が正です。

スケジュールの停車フラグ、乗降・積載、発車枠と発車時刻、他編成待ち、スケジュールウィンドウの操作について、wiki に載っていない細部をまとめる。

## 停車フラグと乗降の扱い

### 同じ駅に複数回停車するスケジュールの乗降・経路

乗車不可（no_load）・降車不可（no_unload）・全員降車（unload_all）は、同じ駅に複数回停車するスケジュールでも期待どおりに働く。

- 一度 no_load でない状態で停車していれば、別の停車が no_load でも、その駅からの旅客経路は生成される。
- 次のその駅の停車が no_load の場合、その手前の停車では、さらに先の駅まで乗車する。次の停車が no_load でなければ、従来どおりそれ以降の駅へ行く客は乗車しない。
- 停車駅が no_unload なら車両から降りない。unload_all なら全員降りる。
- 上の変更の副作用で、全員降車を含む折り返しスケジュールで接続（コネクション）が張られなくなる不具合が出て、同日に修正された。例は A,B,C,D,E(全員降車),D,C,B で、C 駅から B・A 駅へ行けなくなっていた。原因は no_load の区間の状態が折り返し後にリセットされなかったこと。
- 出典: [#91](https://github.com/teamhimeh/simutrans/pull/91)（2025-05-11 マージ）、[#111](https://github.com/teamhimeh/simutrans/pull/111)（2025-07-20 マージ）、リリース v44_4・v44_5
- 関連する wiki: [OTRP-Home](https://github.com/teamhimeh/simutrans/wiki/OTRP-Home)（各ボタンの意味のみ。複数回停車時の扱いは記載なし）

### 停車フラグの値と「乗車区間を区切る」の働き

自動テスト（#394）の説明に、停車フラグの値と、全員降車・乗車区間を区切る（V）の違いが書かれている。

| フラグ | 値 |
|---|---|
| NO_LOAD | 4 |
| NO_UNLOAD | 8 |
| UNLOAD_ALL | 32 |
| TRANSFER_INTERVAL（乗車区間を区切る） | 128 |

- 全員降車は、その停留所が乗換地点（transfer halt）になり、その先の接続を探索できる。
- 乗車区間を区切るは、乗換地点にはならず「区間の境界」として働く。区間をまたぐ直通経路（例: A から E）は存在せず、区間内の経路（A→D、C→E）は使える。
- 出典: [#394](https://github.com/teamhimeh/simutrans/pull/394)（2026-02-18 マージ）
- 関連する wiki: [スケジュールウィンドウの説明](https://github.com/teamhimeh/simutrans/wiki/%E3%82%B9%E3%82%B1%E3%82%B8%E3%83%A5%E3%83%BC%E3%83%AB%E3%82%A6%E3%82%A3%E3%83%B3%E3%83%89%E3%82%A6%E3%81%AE%E8%AA%AC%E6%98%8E)（「乗車区間を区切る(V)」は項目名のみ、動作の説明は記載なし）

### 所要時間ベース経路探索での臨時乗車・臨時降車

### 駅を通過する（P）と、乗降客がいなければ通過する（G）

「この駅を通過（P）」は v49 で追加された。押した駅は no_load と no_unload が付いた扱いで、駅ではなく中継点として通過する。

- 中継点として通るので、振り分け（振分信号）は動作しない。ルートの終端ではなく途中として扱うため、減速もしない。
- 振分信号→中継点→連結試行駅の並びでは、振分信号を無視して通る。中継点→振分信号→連結試行駅の並びでは、振分信号で一時停止する（作者の確認結果）。後者で信号を冒進する不具合が v47_3_3 で直った。
- 通過にした駅は、駅の編成一覧・路線一覧に載らず、地図の路線図でも中継点と同じ扱いになる（v55_10）。経路探索には影響しないはずと作者が明記している。
- 「乗降客がいなければ通過（G）」は、中継点は必ず通り、駅では乗降の有無を調べて、無ければ「次の駅へ」ボタンと同じ動きをする（v49）。

### 乗降客がいなければ通過（G）の区間指定と「1 行先のみ積載」

## 積載・過積載・降車

### 過積載の細部

過積載（v50 で追加）には、wiki に無い次の点がある。

- 旅客の最大乗車率が 100% を超えて効くのは、全体の過積載許可が有効なときだけ。それ以外は 100% が上限（PR のレビューより）。
- 積むまで待機と最大乗車率の、100% 以上の刻み幅は 50% 単位（150% など）。
- 積むまで待機の欄に「最大乗車率まで待機」と「積むまで待機を解除」のボタンがある（v51_2）。
- 過積載時の停車時間と重量計算も調整された、と PR のチェックリストにある。具体的な式は PR から分からない。

- 出典: [#242](https://github.com/teamhimeh/simutrans/pull/242)（2026-01-03 マージ）、[#255](https://github.com/teamhimeh/simutrans/pull/255)（2026-01-04 マージ）、[#362](https://github.com/teamhimeh/simutrans/pull/362)（2026-02-11 マージ）、リリース v50・v51_2
- 関連する wiki: [OTRP-Home](https://github.com/teamhimeh/simutrans/wiki/OTRP-Home)「過積載について」（3 つのチェックのみ）

### 過積載時の応荷重制御（`overloaded_acceleration`）

過積載時の応荷重制御の重量の扱いを切り替える設定 `overloaded_acceleration` がある（v57_0_1）。`simuconf.tab` に `overloaded_acceleration=1` と書いても設定でき、セーブに保持される。既定は OFF。

- OFF: 従来どおり、100% 満載相当で応荷重制御を行う。
- ON: スケジュールの最大乗車率（例 200%）の重量で換算する。OFF より発車加速が低く、実効重量が大きくなる。
- スケジュールの応荷重制御が無効なら、この設定は加速に影響しない。

- 出典: [#593](https://github.com/teamhimeh/simutrans/pull/593)（2026-07-11 マージ）、リリース v57_0_1
- 関連する wiki: [OTRP-Home](https://github.com/teamhimeh/simutrans/wiki/OTRP-Home)（応荷重制御は「満載時の加速度」とだけ記載。過積載との組み合わせは記載なし）

### 編成詳細ウィンドウの「次の駅で全員降車」ボタン

編成詳細ウィンドウのボタンで、次の駅で積載中の旅客・貨物をすべて降ろせる（v57_0_1）。

- 次の駅のホーム長によらず降ろす（ホーム長違反を無視する）。
- 次の駅が降車不可（no_unload）なら、その駅では降ろさず通過する。フラグは残る。
- 降車処理をすると、フラグはリセットされる。フラグはセーブされる。
- 回送（no_load）と併用すると、降ろした後は客が乗らない。併用しなければ、降ろした後に通常営業に戻る。ホーム長からはみ出す分には乗れない。
- v58_1 以降は、駅に停車中に押すと、その駅で即座に全員を降ろす（降車不可の駅を除く）。同時に回送（no_load）が付くので、再び乗車させるには回送を解除する。発車時刻待ちの編成でも使える。状態の判定ずれを避けるため、状態によらず常に回送が付く。

- 出典: [#653](https://github.com/teamhimeh/simutrans/pull/653)（2026-07-11 マージ）、[#675](https://github.com/teamhimeh/simutrans/pull/675)（2026-07-22 マージ）、リリース v57_0_1・v58_1
- 関連する wiki: 記載なし（スケジュールの「全員降車」とは別の機能）

## 発車枠と発車時刻

### 発車枠は発車条件が整うまで予約しない

発車時刻（発車枠）は、発車条件が整うまで予約しない。貨物の 100% 積載待ちとダイヤを両立させるための機能（v45）。

- 「連結するまで発車しない」: 連結が完了するまで枠を取らない。
- 「積むまで待機」を有効にした場合: 積載の待機を満たすまで枠を取らない。v62_5_2 で、積むまで待機と発車時刻待ちを併用したときもこの動きになるよう直った。
- 積載率の指定と月間発車本数を併用すると、長時間待機した編成が条件を満たしたとき、到着時刻から計算した過去の枠を取り、複数編成が続けて発車することがあった。初回の予約は、予約を試みる現在時刻から枠を探すよう直った。発車許可待ち・連結完了待ち・最大待機時間による解除・運休からの再開にも同様に適用される。予約を取った後は、その時刻を保持して枠を後ろへ送らない。公開 API・設定項目・セーブ形式の変更はない（#793）。
- 連結関連の補足: 「連結完了まで枠を取らない」ボタンは常に表示され、子編成だけが連結待機でも扱える（v45_1）。「出発直前に積載」は連結した子編成でも働く（v45_3）。

- 出典: [#115](https://github.com/teamhimeh/simutrans/pull/115)（2025-07-28 マージ）、[#125](https://github.com/teamhimeh/simutrans/pull/125)（2025-08-09 マージ）、[#159](https://github.com/teamhimeh/simutrans/pull/159)（2025-09-09 マージ）、[#793](https://github.com/teamhimeh/simutrans/pull/793)（2026-10-31 マージ）、リリース v45・v45_1・v45_3・v62_5_2
- 関連する wiki: [増解結機能-Coupling](https://github.com/teamhimeh/simutrans/wiki/%E5%A2%97%E8%A7%A3%E7%B5%90%E6%A9%9F%E8%83%BD-Coupling)（連結待ちで枠を取らない点のみ）

### 「次の駅へ」と発車枠、停車中に押したときの処理

- 「次の駅へ」を押しても、発車枠は解放されない。航送や連結のときの発車枠の扱いも直った（v62_5_1。リリースの表現は「発車枠の取得・解放手順を修正」）。
- 駅に停車中に「次の駅へ」を押すと、停車時間などの挿入処理を行い、一部のフラグを上書きする。所要時間ベースへの影響を減らし、フラグの書き換え忘れで次の駅から発車できなくなる不具合を防ぐ。リリースノートでは、発車時刻の記録を更新する、と書かれている（v60_1_1）。

- 出典: [#754](https://github.com/teamhimeh/simutrans/pull/754)（2026-10-26 マージ）、[#710](https://github.com/teamhimeh/simutrans/pull/710)（2026-09-03 マージ）、リリース v62_5_1・v60_1_1
- 関連する wiki: [増解結機能-Coupling](https://github.com/teamhimeh/simutrans/wiki/%E5%A2%97%E8%A7%A3%E7%B5%90%E6%A9%9F%E8%83%BD-Coupling)（「次の駅へ」で分割される点のみ。発車枠・所要時間への影響は記載なし）

### 路線間の発車枠の共有：路面電車と鉄道、内部の持ち方

- 路面電車（tram）と鉄道の発車枠を共有できる（v53_0_2）。v53 で発車枠共有のデータ型を `int64` から `linehandle_t` に変えたことで可能になった。
- 発車枠グループの ID は路線のハンドル（`linehandle_t`）で持つ。路線を削除するとき、その ID を発車枠グループに持つ他の路線の値を書き換える必要がある（ID が使い回されるため。レビューでの指摘と、作者の対応済みの返信）。
- スケジュールの文字列の読み込みでは、`departure_slot_group_id` と `next_line_id` を 32 ビットで読む（以前は 16 ビットに切っていた。2026-05-10 マージ）。
- 未マージの案として、発車枠グループの比較を「スケジュール内の番号」から「次の駅」に変え、一部区間だけの路線共有でも枠を共有できるようにする PR（#781）がある。2026-10-25 に下書きに戻された。この案が入ると、wiki の共有条件が変わる。

### 発車時刻の桁あふれによる早発・長時間待機

内部の時間（ticks）が 32 ビットの上限付近に達する場面で、発車時刻の予約がずれ、早発や極端に長い待機になる不具合が直された。

- 大小比較が、値が 1<<32 をまたぐ場合を正しく扱っていなかった（v49）。2 つの値の差が 1<<31 を超えるときは、値が 1<<32 をまたいだとみなして大小を反転する。
- ticks がリセットされるとき、駅の発車記録と編成の発車予定時刻も同時にリセットする（v50_4）。
- 長時間経過したマップで一部の発車枠が予約できなくなる不具合（v40）、スケジュールの出発時刻処理の強化（v44_4）も同系統の修正。

- 出典: [#236](https://github.com/teamhimeh/simutrans/pull/236)（2025-12-27 マージ）、[#306](https://github.com/teamhimeh/simutrans/pull/306)（2026-01-24 マージ）、[#103](https://github.com/teamhimeh/simutrans/pull/103)（2025-07-06 マージ）、リリース v40・v44_4・v49・v50_4

## 他編成を待つ・発車させる

### 他編成の到着を待機する機能の細部

wiki（スケジュールウィンドウの説明「他編成の到着を待機」）にある基本の使い方に加えて、次の点が PR で確認されている。

- 効果があるのは、同じ駅にいる他編成だけ。
- 待機側の編成は、フラグだけを使う。どの路線を発車させるかは、発車させる側の編成が指定する。
- 対象の編成が複数いるときは、1 編成ずつ許可される。対象がいなくてもゲームは進む。
- 待機側が連結中なら、連結中のすべての編成の許可が出るまで待つ。許可する側が連結中なら、同時に複数編成を許可できる。
- 駅を通過するときにも、発車許可を出せる。この場合、その駅での「他編成を発車させるまで停車」は無効。折り返す通過駅でも、待機中の編成を発車させられる。
- 選べる路線は、他の waytype・他社の路線にも広がり、同じ駅に乗り入れる路線だけが表示される。路線の指定は発車枠グループの単位で、同じスケジュールの路線は同じ枠として扱われる。

- 出典: [#683](https://github.com/teamhimeh/simutrans/pull/683)（2026-08-09 マージ）、[#694](https://github.com/teamhimeh/simutrans/pull/694)（2026-08-20 マージ）、リリース v59_0_2・v60_0_1
- 関連する wiki: [スケジュールウィンドウの説明](https://github.com/teamhimeh/simutrans/wiki/%E3%82%B9%E3%82%B1%E3%82%B8%E3%83%A5%E3%83%BC%E3%83%AB%E3%82%A6%E3%82%A3%E3%83%B3%E3%83%89%E3%82%A6%E3%81%AE%E8%AA%AC%E6%98%8E)（概要のみ。同一駅限定、複数対象の扱い、通過駅での扱いは記載なし）

## スケジュールウィンドウの操作・表示

### エントリの並べ替えと詳細設定の一括展開

- 各エントリとスケジュール詳細に上下ボタンがあり、削除して入れ直さなくても順序を変えられる（v51_1）。
- 「先頭へ」ボタンを押してからエントリをクリックすると、そのエントリが先頭になるよう並べ替える。A→B→C→D で C を選ぶと C→D→A→B になる。並べ替えの後は追加モードに戻り、ボタンの押下状態が解除される（v62_2）。
- Ctrl を押しながらスケジュールウィンドウを開くと、すべての詳細設定を展開した状態で開く（v51_2）。

- 出典: [#350](https://github.com/teamhimeh/simutrans/pull/350)（2026-02-06 マージ）、[#749](https://github.com/teamhimeh/simutrans/pull/749)（2026-10-12 マージ）、[#364](https://github.com/teamhimeh/simutrans/pull/364)（2026-02-11 マージ）、リリース v51_1・v51_2・v62_2
- 関連する wiki: [スケジュールウィンドウの説明](https://github.com/teamhimeh/simutrans/wiki/%E3%82%B9%E3%82%B1%E3%82%B8%E3%83%A5%E3%83%BC%E3%83%AB%E3%82%A6%E3%82%A3%E3%83%B3%E3%83%89%E3%82%A6%E3%81%AE%E8%AA%AC%E6%98%8E)（これらのボタンは記載なし）

### 待機時間・発車時刻の時間表記

- 積むまで待機の最大待ち時間は、月あたりの値に加えて、`h:m:s` と、発車時刻指定と同じ divisor 基準の表記でも表示される（v50_1）。
- 積むまで待機で最大待ち時間を設定している場合、編成の状態表示に待機時間が出る。単位はダイヤと同じ（v51）。
- 発車時刻まわりの入力欄（積むまで待機の待ち時間、発車時刻のオフセット、遅延許容時間）は、24 時間表記の `hh:mm:ss` で入力できる（v58_0_2）。
- 路線の所要時間（journey_time_info）も `hh:mm:ss` で表示できる（v50_1）。

- 出典: [#260](https://github.com/teamhimeh/simutrans/pull/260)（2026-01-08 マージ）、[#329](https://github.com/teamhimeh/simutrans/pull/329)（2026-01-31 マージ）、[#652](https://github.com/teamhimeh/simutrans/pull/652)（2026-07-17 マージ）、[#261](https://github.com/teamhimeh/simutrans/pull/261)（2026-01-08 マージ）
- 関連する wiki: [スケジュールウィンドウの説明](https://github.com/teamhimeh/simutrans/wiki/%E3%82%B9%E3%82%B1%E3%82%B8%E3%83%A5%E3%83%BC%E3%83%AB%E3%82%A6%E3%82%A3%E3%83%B3%E3%83%89%E3%82%A6%E3%81%AE%E8%AA%AC%E6%98%8E)（最大待ち時間は「1/n か月」とだけ記載）

### スケジュールの全ルート表示と 1 周の所要時間の概算

編成・路線のスケジュールの全区間のルートを地図に表示し、1 周（1 往復）の所要時間を概算して表示する（v60_1_1）。

- ルートが無い区間があると、所要時間の欄に「NO ROUTE!」と警告が出る。スケジュールを組んだ時点でルートがつながっているかの確認にも使える。
- next_line を設定している場合、最後の駅から最初の駅までのルートだけが無くても、所要時間を計算できる。
- 概算の計算方法は、駅の到着時刻の概算と同じ。1 周の推定所要時間の算出の誤りは翌日の修正で直り、1 周の総タイル数も表示される（#718）。

- 出典: [#712](https://github.com/teamhimeh/simutrans/pull/712)（2026-09-04 マージ）、[#718](https://github.com/teamhimeh/simutrans/pull/718)（2026-09-05 マージ）、リリース v60_1_1
- 関連する wiki: 記載なし

### スケジュール単位の自動反転（reverse_by_default）

折り返しで自動的に編成を反転する設定 `reverse_by_default` を、マップ全体だけでなく、スケジュール単位でも設定できる（v51）。マルチプレイでの利用を想定している。

- マップ側の `reverse_by_default` が OFF のときだけ有効。
- 列車系のみ有効。
- スケジュール全体のフラグとして保持する。
- スケジュールウィンドウを開き直したときにチェックボックスの設定が復元されない不具合は、v55_9 で直った。

- 出典: [#328](https://github.com/teamhimeh/simutrans/pull/328)（2026-01-31 マージ）、リリース v51・v55_9
- 関連する wiki: [OTRP-Home](https://github.com/teamhimeh/simutrans/wiki/OTRP-Home)（マップ単位の設定のみ。スケジュール単位は記載なし）

### スケジュール移動ツール（停車駅移動ツール）

停車駅を別の駅に付け替えるツール（`general_tool[31]`）は、リリースノートでは「停車駅移動ツール」「スケジュール移動ツール」、PR では「Replace Stop（スケジュール移動）」と呼ばれる。

- 他社の乗り入れを許可した駅でも、自社のスケジュールに使える（v44_2）。
- Ctrl を押しながら移動すると、そのマスのスケジュールだけを移動する。同じホームの他のマスは動かさない（v46）。
- 2 タイル以上のホームで、クリックしたタイルとスケジュール登録のタイルが違うと移動が反映されない不具合があった。ホームの端のタイルが走査から抜け落ちていたのが原因。隣り合う別の停車場のタイルが混ざる問題もあわせて直った（v55_3）。対象は道路・鉄道・路面電車など。水路と空路は別の処理で影響しない。

**wiki との違い:** ツール定義は `general_tool[31]`（TOOL_STOP_MOVER）を「乗り物を停止させる」と説明している。リリースノートは、同じ `general_tool[31]` を「停車駅移動ツール」と呼んでいる。

- 出典: [#538](https://github.com/teamhimeh/simutrans/pull/538)（2026-05-27 マージ）、[#173](https://github.com/teamhimeh/simutrans/pull/173)、[#77](https://github.com/teamhimeh/simutrans/pull/77)（この 2 件はリリースノートの記述による）、リリース v44_2・v46・v55_3
- 関連する wiki: [ツール定義](https://github.com/teamhimeh/simutrans/wiki/%E3%83%84%E3%83%BC%E3%83%AB%E5%AE%9A%E7%BE%A9)（記述が古い）

## 所要時間の記録の保持

### スケジュールを変えたとき・保存したときの所要時間

路線・編成が記録している所要時間（journey_time）は、次の場合に保持される。

- スケジュールウィンドウを開いて何も変えずに閉じても、所要時間のデータはリセットされない（v40）。
- スケジュールの小さな変更では、前の駅と自分の駅が変わらなければ、その記録を残す（v58_3）。フラグの変更も本来は影響するが、運行を続ければ直るので従来とほぼ同じ挙動とされている。
- A→B→C を A→X→C に変えたとき、C に残る B→C の所要時間が残らないよう、ある位置の駅が変わったら次の位置の所要時間もリセットする。
- セーブ・ロードをまたいで引き継がれる（v50）。

- 関連する wiki: [所要時間ベース旅客経路探索について](https://github.com/teamhimeh/simutrans/wiki/%E6%89%80%E8%A6%81%E6%99%82%E9%96%93%E3%83%99%E3%83%BC%E3%82%B9%E6%97%85%E5%AE%A2%E7%B5%8C%E8%B7%AF%E6%8E%A2%E7%B4%A2%E3%81%AB%E3%81%A4%E3%81%84%E3%81%A6)（スケジュール変更時の扱いは記載なし）
