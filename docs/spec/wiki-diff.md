# wiki と食い違う点・wiki の記述が古い点

> この内容は、OTRP の PR とリリースノートの記述から拾い、OTRP v63_4 のソースコードと照らし合わせたものです（2026-11-21）。wiki は 2026-11-21 時点のものと比べています。ゲームを動かしての確認はしていません。仕様は [OTRP wiki](https://github.com/teamhimeh/simutrans/wiki/OTRP-Home) が正です。

各ページで「wiki との違い」として挙げた点の一覧。wiki を直すときの手がかりにする。根拠は、それぞれのページの項目にある。

## 信号・閉塞

ページ: [信号・閉塞](/spec/signal)

- **一部だけ電化されたホームにも電車が入れる**: 「信号システムについて」の振分信号の項は「一部だけ電化していないホームについては電車が入線できません」とあるが、v48_2（2025-12-22）以降は古い記述。「電化の取り扱いについて」の「一部のみ電化されているホームでは電化されている長さを加味」のほうが現行に近い。
- **連結待機信号・振り分け信号を使わなくても、同じホームなら連結できる**: 「増解結機能-Coupling」は、連結直前に「連結相手がいる時のみ進入を許可」の振り分け信号を必ず通るよう求め、経由しない場合は連結成功を保証できないと書いている。v62_0_3 以降は、同じホームにいれば信号なしでも連結できる。
- **優先信号は通過のたびに再評価する**: 「信号システムについて」は、v47_3 以降、次の信号が振り分け信号・ロングブロックシグナルの場合に優先信号の現示は黄色になると書いている。v53 のリリースノートは、この黄色現示を不具合として修正したと書いている。
- **出発信号の予約解除の不具合**: wiki は「(v53 時点) 1 マスの列車の場合、予約が解除されてしまう不具合があるようです」と書いている。#452 の修正対象（始発タイル）と同じ事象かは、原文からは断定できない。
- **線路占有解除ツールと連結中の編成**: 「増解結機能-Coupling」の Q&A は「線路の予約解除ツールを使用して連結中の編成をクリックすると分割します」と書いている。v60_2 以降は分割されない。

## 連結・反転・車庫

ページ: [連結・反転・車庫](/spec/coupling)

- **振り分け信号・連結待機信号なしでも、同じホームなら連結できる（v62_0_3 以降）**: wiki の Q&A は「連結直前に必ず振り分け信号を通ること」「経由せず入線した場合は連結成功を保証できない」と書く。v62_0_3 以降は、信号なしでも連結できる場合がある。
- **線路占有解除ツールで連結中の子編成は分割されなくなった**: wiki の Q&A は「`b` ボタンで予約解除ツールを使い、連結中の編成をクリックすると分割する」と書く。v60_2 で、この挙動は不具合として修正された。
- **反転したまま車庫に入出庫できる**: wiki は「反転した編成を、編成ウィンドウのボタンで車庫に送ると、車両の向きと連結順序が通常に戻る」と書く。v63_4 では、入庫すると車庫内の車両の並びは通常に戻るが、反転していたことは車庫の「向きを反転」の設定として残り、出庫すると反転した状態で出る。
- **連結入出庫の細部**: wiki「連結入出庫機能」は「連結予定の各編成が、単独で出庫可能な編成（編成の出力が 0 より大きい、など）である必要がある」と書く。v44_5 以降は、出力 0 の編成も、動力のある編成と連結して出庫できる。出庫の条件の一つは、連結全体の合計出力が 0 より大きいこと（連結の不完全な編成の出力は 0 として数える）。

## スケジュール・発車・積載

ページ: [スケジュール・発車・積載](/spec/schedule)

- **所要時間ベース経路探索での臨時乗車・臨時降車**: 「所要時間ベース旅客経路探索について」は、所要時間に関わらず積載する例外として臨時系統だけを挙げている。臨時乗車・臨時降車の停車エントリも、この修正（2026-01-27 マージ、リリース v50_5）以降は同様に積載される。
- **乗降客がいなければ通過（G）の区間指定と「1 行先のみ積載」**: スケジュールウィンドウの説明の「乗降客がいない場合経由しない(G)」は v49 時点の説明で、区間指定と 1 行先モードは書かれていない。
- **スケジュール移動ツール（停車駅移動ツール）**: ツール定義は `general_tool[31]`（TOOL_STOP_MOVER）を「乗り物を停止させる」と説明している。リリースノートは、同じ `general_tool[31]` を「停車駅移動ツール」と呼んでいる。

## 旅客経路探索・所要時間

ページ: [旅客経路探索・所要時間](/spec/route-search)

- **貨物カテゴリごとの切り替えと、積載順序（FIFO）**: OTRP-Home は `first_come_first_serve`（既定は無効）を「先に来た乗客から乗る」設定とだけ書く。v55_10 以降は、OFF でも所要時間ベースのカテゴリは FIFO になる。
- **臨時乗車・臨時降車の駅は最速編成でなくても乗降できる**: wiki の積載ルールは、所要時間に関わらず積載する例外として「臨時系統」と「所要時間の実績が無い区間がある編成」だけを挙げる。臨時乗車・臨時降車のエントリも例外になる（#314、2026-01-27 マージ）。
- **実績の無い区間の仮の所要時間**: アーカイブの仕様案ページには「目的地までのユークリッド距離/路線の 1 番目の編成の最高速度」とあるが、実際の距離は x の差と y の差の和で、5 倍にする点は載っていない。現行ページには仮の所要時間の記述が無い。
- **路線の所要時間ウィンドウの内容**: wiki は「路線ごとに駅間所要時間を表示できる」「`路線所要時間` ボタンで実績を確認できる」とだけ書く。表示の内訳、累計、hh:mm:ss は載っていない。
- **乗換経路検索ウィンドウ（`dialog_tool[36]`）**: wiki は `dialog_tool[36]` で最速経路を確認できると書くだけで、数値の意味、貨物の検索、地図表示は載っていない。

## 駅・会社・ネットワーク・収支

ページ: [駅・会社・ネットワーク・収支](/spec/halt-company-network)

- **公共化（ctrl）と私有化（shift）の細かい仕様**: wiki は shift・ctrl の概要のみで、way・信号チェックの省略、標識の範囲、私有化時の軌道の扱いは記載がない。
- **駅の集客範囲を waytype ごとに変更**: wiki の「所要時間ベース旅客経路探索について」は、徒歩連絡を「2 つの駅の集客範囲が互いに被っている場合」に有効とだけ書く。waytype ごとに範囲が変わった後の判定は、この PR の記述（互いの有効範囲内に入ること）が新しい。
- **斜めタイル・勾配タイルの停留所（追加分）**: wiki は v33_2 時点の暫定仕様として「端のタイルが斜めタイルなら有効長は半分（5.65625）」と書く。1 マスの停留所についてはこの変更が新しい。複数マスの停留所では、端のタイルが斜めタイルのとき、その端のタイルの有効長は今も半分として数える（wiki のとおり）。
- **会社数の上限が 63 社に**: wiki の MCP-Server は `player_nr` を「0〜15」と書く。ゲーム内の MCP ツール（`run_squirrel`）の説明文も 0〜15 と書くが、実際の処理は 0〜63 の値を受け付け、範囲外は 1 にする。
- **信号・標識の維持費と通行料**: wiki で通行料を説明しているのは、航送機能だけ。航送の通行料は `toll_shipping_percentage`、way・信号・架線の通行料は `toll_waycost_percentage` で決まる。

## 道路・線路・電化・航送・航空

ページ: [道路・線路・電化・航送・航空](/spec/way)

- **一部だけ電化されていないホームへの振り分け（v48_2）**: wiki「信号システムについて」の振り分け信号の項は「一部だけ電化していないホームについては電車が入線できません」と書いているが、v48_2（2025-12-22）で変更されている。wiki「電化の取り扱いについて」の「一部のみ電化されているホームでは電化されている長さを加味」は、この変更後の説明と合う。
- **追い越しモードの追加（「一編成専用区間」・「追い越し車線は停車のみ可」）**: wiki の [E]・[S] の説明に、連結待機の編成への進入の例外は書かれていない。
- **1 マスの斜めタイル停留所のホーム長**: wiki「斜めタイル停留所・勾配タイル停留所について」は、v33_2 時点の暫定仕様として「端のタイルが斜めタイルなら有効長は半分（5.65625）」と書いている。複数マスの停留所の端のタイルは、今もこの記述のとおり半分で数える。1 マスの停留所だけは、その後の v50_5（2026-01-27）で変わっている。
- **way の `vehicle_offset` で 1 マスですれ違う（v62_0_3）**: wiki「wayによる車両オフセット機能」は、注意点で「1マスでのすれ違いはできません」と書き、末尾の「鉄道におけるすれ違いについて」では `Direction` モードで同じタイルですれ違えると書いていて、ページ内で食い違っている。#737 は、すれ違える方の機能が入った変更で、v62_0_3（2026-09-26）で入った。注意点の記述は v62_0_3 より前のものと思われる（推測）。
- **航送**: wiki「航送機能」の航行費用の節は、通行料の式を `toll_waycost_percentage` で説明している。v62_0_3（2026-09-26）で通行料の比率は `toll_shipping_percentage` に変わり、運賃収入の分配（`shipping_income_percentage`）も加わった。wiki は 2026-11-18 の更新で「v63 以降は waytype ごとに航送単価を設定できる」と足したが、設定のキー名と、式の比率の変更は書いていない。

## 都市・産業・地図・マップ

ページ: [都市・産業・地図・マップ](/spec/city-industry-map)

- **閉業と「壊されない」フラグ（v48）**: OTRP-Home は閉業モード（v48）と「閉業しない」設定だけを書く。壊されないフラグが撤去ツールにも効くことは載っていない。
- **地図全体を画像に出力する**: wiki の「ミニマップ画像出力ツールの設定」は、書式欄の例で `simple_tool[52]` と書き、概要の表と設定例では `simple_tool[53]` と書いている。リリース v62_2 の記載は `simple_tool[53]`。v63_4 のツールの並びでは、このツールの番号は 53 で、書式欄の `[52]` は誤記と思われる。
- **地形データ（高さマップ）の PNG 出力**: wiki は「(v63_1 より) マップの高度ファイルを出力可能」の一行のみ。リリースノートでは v63_1_2 に載っている。

## 互換性とバージョン

ページ: [互換性とバージョン](/spec/compatibility)

- **本家セーブデータの読込範囲と保存**: OTRP-Home は「v51 では 124.3.1 の pakset・セーブのロードに対応」までで、124.4（v54_0_1）と 125.0.1（v63_0_1）への対応は載っていない。リリースノート側が新しい。
- **makeobj の版と読める pak**: OTRP-Home は「v54 以降は makeobj 60.9 の pak と Extended 用 pak を読める」までで、60.11（v55_9）・60.12（v62_3）は載っていない。
- **pak の貨物を増減してもセーブの設定がずれない（v56）**: wiki は「v55 台（v55_10）以前は貨物アドオンの追加・削除でセーブの経路データが入れ替わる」と書く。v56（2026-07-08）で貨物名を保存する形に直った。
- **Mac 版の配布形態の変遷**: OTRP-Releases-(v31‐v35)（v33_2_2）は「Universal binary、Homebrew でのライブラリのインストールが必要」と書く。v40_1_1（2024-10-05）以降は Homebrew 不要の静的リンク版になり、v46 以降は Apple Silicon 専用になった。OTRP-Home の Mac の項は xattr の手順だけで、Apple Silicon 専用であることは書かれていない。

## ツール・ショートカット・画面

ページ: [ツール・ショートカット・画面](/tips/tools-ui)

- **公共化・私有化ツール**: wiki は shift を「現在有効なプレイヤー所属の停留所になる」、ctrl を「駅設備を元のプレイヤー所有のまま公共化」と書くだけ。私有化で駅の建物・軌道・架線まで自社のものになること、ctrl を併用すると費用がかからないことは、wiki に記載がない。
- **停車駅移動ツール（スケジュール上の停車位置の移動）**: wiki の説明は「乗り物を停止させる」だが、実際はスケジュールの停車位置を移動するツール。
- **追加された simple_tool**: wiki のミニマップ画像出力の節は書式の例に `simple_tool[52]` と書くが、同じ節の概要と表は `simple_tool[53]`（`TOOL_EXPORT_MINIMAP`）で、表で `[52]` は編成追跡時の表示モード変更。リリース v55_8（`[52]` のモード切り替え）と v62_2（ミニマップ出力は `[53]`）に合わせると、書式の `[52]` は誤記とみられる。同様に OTRP-Home はスクリプト生成を `general_tool[44]` と書くが、表では `[44]` は地表オブジェクトの配置で、スクリプトの生成は `[47]`。

## Squirrel API と MCP サーバー

ページ: [Squirrel API と MCP サーバー](/dev/scripting-mcp)

- **capture_screen ツール**: wiki の MCP-Server は利用可能なツールを `run_squirrel` のみと書いている。`capture_screen` はリリース v55_9（2026-06-27）で追加された。ほかの 2 つ（`export_minimap`・`get_tile_info`）も wiki に記載がない。
- **halt_x.get_connections() の追加項目**: wiki の OTRP-Home は戻り値を `halt`・`weight`・`line` の 3 つとして書いている。`raw_weight`・`is_foot_path`・無効時の `null` は記載がない（#671 は 2026-07-20、#521 は 2026-05-20 のマージ）。
- **schedule_x の追加項目**: wiki の OTRP-Home は schedule_x について `base_waiting_time` しか書いていない。上の項目は v54_0_1 で追加された。
- **gui クラスの追加（画面の操作と取得）**: wiki の OTRP-Home の gui クラスの節は `jump`・`close_all_windows`・`take_screenshot`・`set_zoom` までで、上の 5 つは記載がない（すべて 2026-06-28 マージ、リリース v55_10）。

## 開発の決まり

ページ: [開発の決まり](/dev/rules)

- **`config.default` への書き方**: wiki の同じページの中で、本文は `CFLAGS += -DNEW_FEATURE=1`、末尾の表は「`config.default` に `FEATURE_X = 1` を追加」と書き、食い違っている（wiki の原文に日付は無い）。#506 のメンテナの発言（2026-05-20）は本文の書き方（`CFLAGS +=`）と合う。「ガイドラインを更新する」という予告が wiki に反映されたかは、確かめていない。
- **macOS ビルドの変遷**: OTRP-Home の mac の節は、配布バイナリは Apple の認証を受けていないので `xattr` の操作が要る、と書く。v63_3（2026-11-12）で公証に対応したが、公証済みのビルドでこの操作が要らなくなるかは、PR とリリースノートから読み取れなかった。
