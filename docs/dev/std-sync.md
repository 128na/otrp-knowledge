# 本家と OTRP の修正の追従

> 確かめ済みの範囲の記録: [128na/simutrans#19](https://github.com/128na/simutrans/issues/19)

本家 Simutrans で直った不具合が OTRP に入っているか、OTRP で直した不具合が本家に残っていないかを確かめるときの決まり。
本家は [aburch/simutrans](https://github.com/aburch/simutrans)（SVN の写し）の `master`、OTRP は [teamhimeh/simutrans](https://github.com/teamhimeh/simutrans) の `OTRP-KUTAv6` を指す。

## 要点

- git の上の分岐点は本家の r9281（2020-10-13）。ただし OTRP のソースは 2021-12-12 にまとめて入れ替えてあり、中身は本家の **r10251 前後（2021-11-28）** に近い（見積もり。3 章）。
- OTRP はその後も、本家の修正を 1 件ずつ取り込んでいる。**本家のコミットが OTRP の祖先にあるかでは決まらない。** 修正の中身（足した行・消した行）が OTRP のコードにあるかで判断する。
- 修正が題名の `FIX:` に出ないことがある。半透明の会社の色の不具合（[128na/simutrans#17](https://github.com/128na/simutrans/issues/17)）は、本家では r10846「CODE: reduce code duplication for rgb555/565 specific code」の整理の中で直っていた。
- 本家は r10444 でソースを `src/simutrans/` の下に移し、ディレクトリを分けた。OTRP は根の直下のまま。比べるにはパスの対応が要る（4 章）。
- 確かめ済みの範囲は [#19](https://github.com/128na/simutrans/issues/19) にコメントで残し、次の回はその後だけを見る。

## 4. パスの対応

- 本家は r10444（`cad5011ec`「Reorganised src directories」、2022-02-03）で、ソースを `src/simutrans/` の下に移してディレクトリを分けた。例: `bauer/` → `builder/`、`boden/` → `ground/`、`simworld.cc` → `world/simworld.cc`、`simtool.cc` → `tool/simtool.cc`。
- r10444 より後に、ソースの改名は無い（`git log -M --diff-filter=R cad5011ec..master -- '*.cc' '*.h'`、2026-11-22）。
- 対応は表で持たず、次の順に機械で付ける。
  1. そのままのパス。本家の `src/simutrans/`・`src/` を外したパス
  2. 範囲の中の改名（`git log -M --diff-filter=R --name-status`）をたどった別名
  3. 同じファイル名。複数あれば、ディレクトリ名が多く一致するもの
- 本家が 1 つのファイルを分けたもの。OTRP は分ける前のファイルのまま。

  | 本家 | OTRP | 分けた版 |
  |---|---|---|
  | `vehicle/vehicle_base.cc`・`rail_vehicle.cc`・`road_vehicle.cc`・`air_vehicle.cc`・`water_vehicle.cc` | `vehicle/simvehicle.cc` | r9450・r9458 など（2020-11） |
  | `world/terraformer.cc`、`world/surface.cc` | `simworld.cc` | r10443（2022-02）、r10536（2022-03） |
  | `gui/components/gui_schedule.cc` | `gui/schedule_gui.cc`（分岐点の本家にあった古い画面を OTRP が残している） | 本家 2020-11（`4e57f6dbc`） |

## 5. 仕分けの物差し

コミットごとに、足した行と消した行を相手の対応するファイルと比べる。行は前後の空白を外して空白をつめ、12 文字未満・コメント・`#include`・括弧だけの行は数えない。

| 仕分け | 条件 | 扱い |
|---|---|---|
| 取り込み済み | 足した行の 7 割以上が相手にある | 読まない |
| 取りこぼし候補 | 足した行が 3 割未満しか無く、消した行（古いコード）が半分以上残っている | 手で読む |
| 一部 | それ以外（相手で書き換わっている、一部だけ入っている） | 古いコードが残っているものだけ読む |
| 比べられない | 相手に対応するファイルが無い。ソース以外だけの変更 | 読まない |
| 書き換わり済み | 足した行の半分以上が、その側の最新にもう無い（後のコミットで書き換えた） | 後のコミットで見る |

確かめ（2026-11-22）:

- r10846（`43d7fba9e`）は「取りこぼし候補」に出る。足した 84 行のうち OTRP にあるのは 2 行、消した 222 行のうち 206 行が OTRP に残っていた。
- OTRP が cherry-pick・手で移した本家の 49 件のうち、43 件は「取り込み済み」に出る。残りは、比べる行が無いもの 2 件、「一部」3 件、「取りこぼし候補」1 件（r9541。`simfab.h` の部分は入っていて、`simtool.cc` の部分は OTRP の側で書き換わっていた）。

## 6. 限界

- 行が一致するかで見るので、移動・書き換えた修正は「一部」に入る。`FIX` の題名の「一部」は、古いコードが残っているものを読む。
- 題名で読むものを選ぶと、r10846 のような黙った修正を落とす。題名に `FIX` の無い取りこぼし候補は、題名に目を通して、修正らしいものを読む。
- OTRP→本家の向きでは、`53ca75e21` の中の修正は 1 件ずつに分けられないので確かめられない。
- 本家にしかない機能の修正は、多くが「比べられない」か「一部」に入る。OTRP にしかない機能の修正も同じ。
- 読み手（サブエージェント）1 人の判定は誤りを含む。初回は、重ねて読んだ 7 件のうち 2 件で判定が食い違い、反証探しで取りこぼしの 58 件のうち 11 件に反証が出るか未確定になった（2026-11-22）。

## 7. 記録に書かないこと

- ネットワーク越しに（ほかのクライアントから）届きうる不具合は、記録に場所と中身を書かない。版・題名・重さだけを書き、詳しくは手元に残す。このサイトは公開されていて、OTRP にまだ入っていない修正の場所は、そのまま攻めどころの一覧になるため（2026-11-22）。
