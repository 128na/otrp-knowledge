# world.save_game のネットワーク制限を外した（2026-11-21）

[2026-11-15 の記録](./2026-11-15_script-save-game.md)の続き。PR [teamhimeh/simutrans#812](https://github.com/teamhimeh/simutrans/pull/812)。書いたら変えない。今も使う決まりは [開発 / スクリプトからのセーブ](../dev/script-save-game.md) にある。

## 経緯

- 11-15 の版は、ネットワークゲームでは「サーバー上のスクリプトだけ可、クライアントとサーバー上の MCP は不可」だった。MCP の拒否は、自由度が高すぎるという利用者の判断。クライアントの拒否は、その判断を広げて実装者が足したもので、技術的な根拠は見つかっていない。
- fork 元の contributor から、「クライアントが呼んでも、画面から手動で呼んだときと同様なら、特に禁止する必要は無いのでは」という趣旨の指摘があった。
- コードを確かめた結果、画面からの保存（`gui/loadsave_frame.cc`）も同じ `karte_t::save` を呼び、保存の処理にネットワークかどうかの判定は無かった。スクリプトだけ制限する理由が無いので、制限と `script_vm_t::from_mcp` を外した（コミット `d19f266f6`）。

## 確かめたこと

- ネットワークのサーバーとクライアントのそれぞれの MCP（`run_squirrel`）から `world.save_game` を呼び、どちらも `null` を返して、保存ファイルができた。
- 保存関連の自動テスト 9 件は合格。
- 未確認: クライアントが保存したとき、切断されるかどうか。保存の処理には切断する処理は見当たらない。上の保存の後も、クライアントは MCP に応答した。
