# world.save_game の実装と検証（2026-11-15）

PR [teamhimeh/simutrans#812](https://github.com/teamhimeh/simutrans/pull/812) の作業で、その時点で確かめたことと経緯。書いたら変えない。今も使う決まりは [開発 / スクリプトからのセーブ](../dev/script-save-game.md) にある。

- 対象: `feature/script-save`（`OTRP-KUTAv6` の `20ed2495b` から分岐）、コミット `678ec13a0`・`990c7d78d`・`b91b14982`
- 検証環境: Windows、MinGW・GDI 版、pak128

## 1. 経緯

1. 依頼は「スクリプトから任意の名前でセーブでき、ディレクトリトラバーサルや禁則文字・制御文字・マルチバイトに安全で、受け入れ条件を保証するテストがあること」。専用の呼び出しオプションは設けない。
2. 最初の実装はシナリオ専用で、ネットワークゲームでは使えなかった。
3. 利用者の指摘で、次の 3 点を直した。
   - アドオンの全方位パターンの目視確認や、本体改造時の検証の証跡のために、シナリオ以外のスクリプト（AI・ツール・MCP）からも呼べるようにした。
   - 日付入りの自動保存に使えるよう、ネットワークゲームでも使えるようにした。
   - 読み取り専用の `.sve` を画面から上書き保存すると成功ダイアログが出るのに上書きされず、一時ファイル `.sv_` が残る不具合を直した（元からあった不具合）。
4. さらに利用者の判断で、ネットワークゲームでは「サーバー上のスクリプトは可、MCP は自由度が高すぎるので不可」にした。クライアントは拒否する。

## 2. 自動で確かめたこと

| 確認 | 結果 |
|---|---|
| 検証関数の単体テスト（`tests/test_save_name.py`） | 合格 |
| `test_save_game_*` 9 件（単独プレイ） | 合格。CI でも合格 |
| 読み取り専用の拒否テスト | 修正前のバイナリで失敗、修正後に合格 |
| 保存先の外へのファイル漏れ | 無し（`../`・絶対パス・UNC などの名前で試し、`save/` の外と親フォルダを確認） |
| 作られたファイル名 | `script_save_テスト.sve`、`script_save_é.sve` が名前どおりにできた |
| 単独プレイの MCP（シナリオ以外の VM）から保存 | `null`、ファイルができた |
| サーバー上の MCP | 拒否、ファイル無し |
| クライアント上の MCP | 拒否、ファイル無し |
| サーバーモード（`-server`）で起動したシナリオのテスト | 合格 |

検証関数の最初の版は、`strchr` に渡す文字列のバックスラッシュが 1 つ欠けて、`\` を通していた。単体テストの「`a\b` は拒否」が失敗して気付いた。

## 3. 利用者が手動で確かめたこと

- 読み取り専用ファイルの上書き保存: エラー表示になる。
- 日本語名の保存（ゲーム内から）: 保存できる。
- 単独プレイでシナリオ・ツール: 保存でき、`../` を含む名前は拒否される。
- ネットワークのサーバー上のシナリオ・ツール: 保存できる。クライアントのツールは「only possible on the server」で拒否される。
